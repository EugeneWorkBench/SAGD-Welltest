# SAGD WellTest Mobile — iOS

Offline-first SwiftUI client for SAGD field data capture. This package implements
the layered architecture from the spec design document.

## Running the app

`Package.swift` builds a **library** (`SAGDWellTest`), which cannot launch on its
own. The runnable app is the thin Xcode project in `ios/App/`, which links this
package and presents `SAGDWellTestRootView`.

1. Open `ios/App/SAGDWellTestApp.xcodeproj` in Xcode (full Xcode, not just the
   Command Line Tools).
2. Choose a simulator or a connected iPhone and press Run (Cmd+R).
3. For a real device, set your signing Team (see *Configuration* below, or
   Signing & Capabilities in Xcode) and enable Developer Mode on the phone.

`swift build` / `swift test` from the terminal do **not** work on macOS: the
package uses `BackgroundTasks`, which is unavailable there. Build for iOS
instead:

```bash
xcodebuild -scheme SAGDWellTest -destination 'generic/platform=iOS Simulator' build
```

The Xcode project is generated by `ios/App/generate_project.rb` (needs the
`xcodeproj` Ruby gem). Edit that script, not the `.xcodeproj`, then re-run it:

```bash
cd ios/App && ruby generate_project.rb
```

## Configuration

Settings live in `ios/App/Config/`. `Shared.xcconfig` holds committed defaults
(all empty). Put real values in `Local.xcconfig`, which is **git-ignored**:

```bash
cp ios/App/Config/Local.xcconfig.example ios/App/Config/Local.xcconfig
```

| Setting                  | Purpose                                                       |
| ------------------------ | ------------------------------------------------------------- |
| `SAGD_BACKEND_BASE_URL`  | Backend base URL (`https` required). Empty = offline-only.    |
| `SAGD_BACKEND_AUTH_TOKEN`| Bearer token, if the backend needs one.                       |
| `DEVELOPMENT_TEAM`       | Apple Team ID; survives regenerating the project.             |

Write `https://` as `https:/$()/` in the file, because xcconfig treats `//` as a
comment. Values reach the app through `Info.plist` keys `SAGDBackendBaseURL` and
`SAGDBackendAuthToken`, read by `AppConfiguration.fromEnvironment()`. With no
URL, the app falls back to `https://localhost` and sync fails (records stay
queued locally; nothing is lost).

A token set this way is compiled into the app binary. That is acceptable for a
closed pilot only; a wider rollout needs per-user sign-in.

## Screens

The well list (home) has a bottom toolbar:

| Control  | Screen                                                                 |
| -------- | ---------------------------------------------------------------------- |
| Scan     | QR well lookup with live camera preview; works from local data         |
| Escalate | Geotagged photo escalation (camera, or photo library if no camera)     |
| Subcool  | Subcool estimator (no well or network needed)                          |

Selecting a well opens its production or injection log form.

## Reference data from the backend

At launch and on pull-to-refresh, `AppGraph.refreshReferenceData()` pulls wells
changed since the last pull, then each pulled well's test history and open
maintenance tasks, into the local store. Offline or on failure it changes
nothing. The "since" marker is the newest `updatedAt` returned by the server
(stored in `UserDefaults`), not the device clock.

Limitation: tests and tasks are re-pulled only for wells whose own record
changed.

## Debug sample data

Debug builds with **no** backend URL configured insert five sample wells and one
open task when the well table is empty (`UI/DebugSeedData.swift`). Release
builds never include this, and it is skipped whenever a backend URL is set.

Sample IDs for QR testing: `WELL-P-001`, `WELL-P-002`, `WELL-P-003`,
`WELL-I-001`, `WELL-I-002`.

## Distributing via TestFlight

1. Enroll in the Apple Developer Program; set `DEVELOPMENT_TEAM` in
   `Local.xcconfig`.
2. Decide the final bundle ID (`PRODUCT_BUNDLE_IDENTIFIER` in
   `generate_project.rb`, currently `com.eugenekartey.sagdwelltest`) **before**
   creating the app record in App Store Connect; it is hard to change later.
3. Replace the placeholder icon in
   `ios/App/SAGDWellTestApp/Assets.xcassets/AppIcon.appiconset/`.
4. In Xcode choose *Any iOS Device*, then Product > Archive > Distribute App >
   App Store Connect.
5. Add testers in App Store Connect.

The project declares `ITSAppUsesNonExemptEncryption = NO` and a privacy manifest
(`PrivacyInfo.xcprivacy`, covering UserDefaults and disk-space checks). Confirm
the encryption answer with your compliance contact; an upload may flag further
required-reason APIs used by dependencies.

## Known issues

- **The test suite does not compile** on the current toolchain (Xcode 27.2,
  Swift 6.4): `Arbitrary` conformance and SwiftCheck access errors in about nine
  property-test files under `Tests/`. This predates the changes above and has not
  been fixed, so there is currently no working automated test run.
- The sync and pull paths have not been exercised against a real backend.
- No user sign-in; no crash reporting.

## Layer structure

Source groups under `Sources/SAGDWellTest/` follow the design's dependency rule
(dependencies point downward only):

| Group          | Responsibility                                                      |
| -------------- | ------------------------------------------------------------------- |
| `UI`           | SwiftUI screens, view models, app entry point                       |
| `Domain`       | Pure logic: subcool estimator, validators, well lookup, escalation  |
| `Repository`   | Read/write facade over the local store; assigns sync metadata       |
| `LocalStore`   | SQLite via GRDB + photo blob file store (source of truth on-device) |
| `Sync`         | Connectivity monitor, oldest-first push queue, retry/backoff        |
| `Integrations` | Camera/QR (AVFoundation), location (CoreLocation)                   |
| `Network`      | URLSession REST client for the Cloud_Backend                        |

## Dependencies

| Package                                        | Scope             | Use                      |
| ---------------------------------------------- | ----------------- | ------------------------ |
| [GRDB](https://github.com/groue/GRDB.swift)    | app + library     | SQLite local store       |
| [SwiftCheck](https://github.com/typelift/SwiftCheck) | test target only | property-based testing |

## Property-based testing

`Tests/SAGDWellTestTests/PropertyTesting.swift` provides `pbtArguments()`, which
clamps SwiftCheck to a **minimum of 100 successful iterations** per property.
Each correctness property is tagged
`Feature: sagd-welltest-mobile, Property {n}: {text}` via `propertyName(_:_:)`.
